## 2025-03-06 - Prisma Database Aggregation Replaces O(N) Array Operations
**Learning:** In the `DashboardController`, gathering stats was highly unoptimized because NestJS services retrieved entire datasets (`findAll` for transactions and leads), loading them into memory only for the controller to execute `filter`, `reduce`, and `slice` operations on arrays. As the dataset scales, this leads to an O(N) memory and performance bottleneck on the application layer. Furthermore, fetching operations were sequential, increasing response times.
**Action:** Always prefer using Prisma's robust aggregation features (`aggregate._sum`, `count`) and specific query operations (`where`, `take`, `in`) over fetching all rows and filtering in application memory. Parallelize multiple independent database queries using `Promise.all` to reduce latency.
