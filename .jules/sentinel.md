## 2024-05-24 - Server-Side Request Forgery (SSRF) in Scraper
**Vulnerability:** The `ScraperService` accepted any user-provided URL and directly instructed a headless browser to navigate to it. This allowed attackers to access private IP ranges (e.g., `10.x.x.x`, `192.168.x.x`), localhosts (`127.0.0.1`, `[::1]`), and cloud metadata endpoints (`169.254.169.254`) on behalf of the server.
**Learning:** URL rewriting via Puppeteer request interception can break SNI and TLS certificate validation. Therefore, a lightweight string/URL validation function `isSafeUrl` must block internal IPs, localhosts, and cloud metadata hostnames *before* calling `page.goto()`. This provides SSRF protection without interfering with Puppeteer's HTTPS validation.
**Prevention:** Always validate user-provided URLs before fetching or navigating to them. Use the native `URL` object to extract the hostname, allow strictly `http`/`https` protocols, and block known internal/private IP address ranges, local domains, and IPv6 loopbacks.
