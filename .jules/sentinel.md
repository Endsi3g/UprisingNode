## 2025-03-11 - SSRF Vulnerability in Puppeteer Scraper
**Vulnerability:** The `ScraperService` accepted an arbitrary, unvalidated URL from the user and passed it directly to Puppeteer's `page.goto()`. This created a Server-Side Request Forgery (SSRF) vulnerability where an attacker could probe internal network resources, fetch metadata from cloud metadata services (e.g., `169.254.169.254`), or hit `localhost` endpoints.
**Learning:** Whenever taking a URL from an untrusted user to perform an outbound request (whether via `fetch`, `axios`, or headless browsers like Puppeteer), the URL must be explicitly validated. Relying solely on network isolation or environment configuration is not sufficient.
**Prevention:** Implement a rigorous `isSafeUrl` check that enforces safe protocols (`http`, `https`), blocks `localhost` and other internal hostnames, and rejects common private IP ranges (`10.x.x.x`, `172.16.x.x`, `192.168.x.x`) to prevent unauthorized internal network access via user-provided URLs.
