## 2024-04-12 - Prevent SSRF with Puppeteer Request Interception
**Vulnerability:** The ScraperService accepted arbitrary URLs from user input and fetched them using Puppeteer without resolving the hostname to check for loopback, private, or cloud metadata IP addresses. Additionally, even if the initial URL was validated, Puppeteer could follow HTTP redirects to a restricted IP address. This allowed attackers to probe internal services and bypass firewalls (SSRF).
**Learning:** Validating just the initial URL is insufficient for SSRF protection when using browsers/clients that automatically follow redirects. Furthermore, parsing a URL to check the hostname is prone to bypasses (e.g., DNS rebinding, IPv4-mapped IPv6, `0.0.0.0/8`).
**Prevention:** Enable Puppeteer request interception (`page.setRequestInterception(true)`) and hook `page.on('request')` to validate the resolved IP of *every* outgoing request (including redirects). Use `dns.lookup` to get the actual IP, and block standard loopback/private ranges along with `0.0.0.0/8` and IPv4-mapped IPv6 addresses (`::ffff:...`).
