## 2025-01-28 - SSRF Vulnerability via Puppeteer Redirects
**Vulnerability:** The `ScraperService` is vulnerable to Server-Side Request Forgery (SSRF) because it launches a headless browser and navigates to user-provided URLs without validating the target IPs. Puppeteer will silently follow redirects. An attacker can supply a benign external URL that redirects to internal endpoints (like AWS metadata at `169.254.169.254` or internal services via `127.0.0.1`, `0.0.0.0/8`, `10.x.x.x`).
**Learning:** Validating the initial URL is insufficient for SSRF protection when using browsers/headless-agents that automatically follow redirects. Every individual request must be verified. The IP address must be validated, not just the string structure, to prevent IPv4-mapped IPv6 bypasses.
**Prevention:** Enable Puppeteer request interception (`page.setRequestInterception(true)`). Intercept every outgoing request using `page.on('request', async (request) => ...)`. Validate the requested URL using an asynchronous `isSafeUrl` function that parses the URL, performs DNS resolution (`dns.lookup`), and strictly blocks loopback, private IPv4/IPv6 ranges, and cloud metadata IP addresses (`net.isIPv4`). Ensure unhandled promise rejections are handled properly using `request.isInterceptResolutionHandled()`.
