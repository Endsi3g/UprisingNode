## 2025-03-10 - [SSRF via Unvalidated Puppeteer URL Navigation]
**Vulnerability:** The scraper endpoint accepts a user-provided URL and navigates to it using Puppeteer without validation. This allows Server-Side Request Forgery (SSRF) and Server-Side Request Forgery against the internal network, including accessing cloud metadata services. The endpoint was also entirely unauthenticated, meaning anyone could exploit this to scan the internal network or conduct a Denial of Service (DoS) attack by wasting server resources loading complex pages.
**Learning:** URL rewriting or blocking in Puppeteer request interception (e.g., using `page.on('request')` to abort requests to internal networks) can break SNI and TLS certificate validation in some configurations. A simpler and more robust approach for basic SSRF protection without breaking HTTPS is lightweight URL string validation to block private/metadata hostnames and IPs *before* calling `page.goto()`.
**Prevention:** Always validate user-provided URLs by parsing them with the `URL` constructor and checking the protocol and hostname against a denylist of private IP ranges, localhost, and common metadata IPs before passing them to tools like Puppeteer or `fetch()`. Additionally, ensure sensitive and resource-intensive endpoints are authenticated (e.g., `@UseGuards(JwtAuthGuard)`).
