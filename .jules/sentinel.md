## 2025-02-23 - Insecure JWT defaults and improper configuration evaluation
**Vulnerability:** The application was using hardcoded or default insecure JWT secrets (`process.env.JWT_SECRET || 'secret'`) evaluated statically at module load time, bypassing NestJS dynamic configuration.
**Learning:** Hardcoded fallbacks in authentication configurations (like JWT modules and Passport strategies) are a critical risk, especially if production relies on them silently when environment variables are unassigned. Furthermore, statically evaluating `process.env` at the file-level in NestJS bypasses the `ConfigModule` and makes proper environment separation and testing difficult.
**Prevention:** Always use dynamic module registration (e.g., `JwtModule.registerAsync`) and inject `ConfigService` to evaluate configurations securely at runtime. Explicitly throw fatal errors if critical secrets are missing (using `NODE_ENV !== 'test'` fallbacks solely to prevent crash loops during test execution).
