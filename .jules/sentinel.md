## 2024-03-28 - [Critical] SSRF Protection in Headless Browsers
**Vulnerability:** The ScraperService accepted arbitrary user URLs and navigated to them using Puppeteer without validation. This allowed Server-Side Request Forgery (SSRF), enabling users to reach internal metadata endpoints (like `169.254.169.254`), local applications (localhost), and private subnets from the server's perspective.
**Learning:** URL validation for headless browsers must strictly enforce `http`/`https` protocols and perform robust host validation to prevent accessing private IPs and internal resources. Simple regexes or string matching aren't enough—the `URL` object should be used to reliably parse domains and block internal IP ranges and loopbacks.
**Prevention:** Always validate user-provided URLs using an `isSafeUrl` function that enforces allowed protocols and rejects restricted IP blocks (e.g., `127.0.0.0/8`, `10.0.0.0/8`, `169.254.0.0/16`, `192.168.0.0/16`, `172.16.0.0/12`) and localhost variants before passing them to server-side HTTP clients or headless browsers.
