## 2024-05-24 - Puppeteer SSRF Vulnerability
**Vulnerability:** The `ScraperService` takes a user-provided URL and navigates to it using Puppeteer (`page.goto(url)`). There was no validation to prevent the user from passing internal network URLs (like `http://localhost`, `http://127.0.0.1`, or cloud metadata endpoints like `http://169.254.169.254`). This allows an attacker to scan internal ports, access local services, or read sensitive cloud instance metadata (SSRF).
**Learning:** Even though Puppeteer is running in headless mode, it executes within the network namespace of the host (or container). Any URL passed to `page.goto` is resolved from that network perspective. Failing to validate user input before passing it to a highly privileged operation like headless browsing is a classic SSRF attack vector.
**Prevention:** Implement strict URL validation before calling `page.goto`. Ensure the URL parses successfully, uses only `http` or `https` protocols, and crucially, block the hostname from resolving to local loopback addresses (IPv4 `127.0.0.0/8`, IPv6 `[::1]`), internal subnets (e.g., `10.0.0.0/8`, `192.168.0.0/16`), and known cloud metadata IP addresses (`169.254.169.254`).
