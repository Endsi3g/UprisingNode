## 2024-11-20 - Prevented Server-Side Request Forgery in Scraper Service
**Vulnerability:** The scraper service accepted user-provided URLs and navigated to them blindly using Puppeteer. This allowed attackers to provide internal or private addresses like `http://localhost`, `http://169.254.169.254` (cloud metadata), or private network ranges (`10.x.x.x`), leading to potential SSRF (Server-Side Request Forgery). The application could be leveraged to access restricted internal services or metadata.
**Learning:** External navigation points (like Puppeteer `goto` methods, `axios.get`, or `fetch`) need rigid network boundary validations. Simple string checks are often flawed, as URLs can be constructed in tricky ways.
**Prevention:** Implement strict network boundary validation checks using native `URL` parsing to isolate the domain logic. Explicitly allow lists of valid external protocols (`http`/`https`) and strictly check the parsed hostname to block any reference to loopback adapters, private IP subnets, cloud metadata IPs, and localhosts before dispatching external web requests.
