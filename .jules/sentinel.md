## 2025-02-14 - Fix Hardcoded JWT Secret Fallback
**Vulnerability:** A hardcoded default value (`'secret'`) was used as a fallback for `process.env.JWT_SECRET` in both `AuthModule` (`auth.module.ts`) and `JwtStrategy` (`jwt.strategy.ts`). This is a critical security vulnerability as it allows tokens signed with the hardcoded secret to be accepted if the environment variable is missing.
**Learning:** In NestJS `JwtModule` and Passport strategies, throwing errors at the file-evaluation level when enforcing secure configuration can break the test suite imports. The correct approach is to throw inside `useFactory` (using `JwtModule.registerAsync`) or inside the class `constructor` so the test suite can mock the configuration or environment successfully before instantiation.
**Prevention:** Always use `registerAsync` for dynamic configuration enforcement, throwing runtime errors inside constructors or factory functions for missing security-critical environment variables rather than falling back to unsafe hardcoded defaults.
