## 2025-02-13 - SSRF Vulnerability via Puppeteer Redirects
**Vulnerability:** The scraper service (`ScraperService`) accepted user-provided URLs and passed them directly to Puppeteer without robust validation against private IPs. Even if the initial URL was validated, Puppeteer's default behavior of automatically following HTTP redirects allows an attacker to bypass initial URL checks by providing a safe URL that redirects to an internal, private, or loopback IP address (SSRF).
**Learning:** Validating the initial input URL is insufficient when using headless browsers like Puppeteer, as they handle redirects transparently. An attacker can set up a public server that redirects `http://attacker.com/safe` to `http://169.254.169.254/latest/meta-data/` or `http://127.0.0.1:3000`.
**Prevention:** To effectively prevent SSRF in Puppeteer, enable request interception (`page.setRequestInterception(true)`) and asynchronously validate every intercepted request (`page.on('request', async (request) => { ... })`) against a strict allowlist or denylist of IP addresses before allowing it to continue. This ensures that any redirected requests are also subjected to the same security checks.
