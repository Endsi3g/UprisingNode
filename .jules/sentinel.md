
## 2024-05-18 - SSRF Vulnerability in Scraper Service
**Vulnerability:** The ScraperService allowed unvalidated user input to be passed directly to `puppeteer.launch() -> page.goto(url)`. This was a Server-Side Request Forgery (SSRF) vulnerability. An attacker could use this endpoint to make the server perform HTTP requests to internal IP addresses (e.g. localhost, private subnets) or cloud provider metadata endpoints (e.g. 169.254.169.254) which are typically restricted. It could also have allowed using other protocols like `file://`.
**Learning:** Using an external library like Puppeteer to fetch resources dynamically based on user input introduces significant SSRF risks if the URLs are not strictly controlled and validated. Validating URLs must ensure the protocol is `http:` or `https:`, and perform DNS resolution to verify the resulting IP addresses are not part of loopback, internal, private, or cloud metadata ranges, to prevent domain rebinding and hostname obfuscation attacks.
**Prevention:** Always sanitize and validate user-supplied URLs before passing them to an HTTP client or headless browser. Use Node's built-in `dns` and `URL` to resolve and check IPs against blocked ranges. Ensure strict protocol allowlisting.
