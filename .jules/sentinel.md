## 2026-01-30 - [SSRF Vulnerability in Scraper Service]
**Vulnerability:** The ScraperService.scrapeCompany method accepted an arbitrary URL parameter and navigated to it using Puppeteer without validation. This allowed Server-Side Request Forgery (SSRF) where a malicious actor could pass a localhost or private network URL (e.g., http://127.0.0.1:3000, http://169.254.169.254) and the server-side browser would execute the request, potentially exposing internal services or cloud metadata endpoints.
**Learning:** Puppeteer's `page.goto` allows navigating to local addresses, meaning user-provided URLs must always be validated not only for format/protocol but also for their DNS-resolved IP addresses to prevent local network scanning or exploitation. Because Puppeteer evaluates HTML and might make subsequent requests (images, sub-frames, redirects), request interception is required to validate every single request made during the scrape.
**Prevention:** Always use `dns.lookup` to check the resolved IP against a list of private and loopback ranges before allowing a request. For tools like Puppeteer, enable request interception (`page.setRequestInterception(true)`) and hook into `page.on('request', ...)` to validate the initial URL, redirects, and all sub-resources continuously.
