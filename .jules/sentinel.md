## 2024-05-18 - SSRF Vulnerability via Puppeteer
**Vulnerability:** The application was passing unvalidated user-provided URLs directly into Puppeteer `page.goto()`. This allowed Server-Side Request Forgery (SSRF), permitting users to access internal network services, private IP ranges (e.g., localhost, 10.x.x.x), and cloud metadata endpoints (e.g., AWS 169.254.169.254) from the backend server's perspective. It also leaked error stack traces on failures.
**Learning:** Puppeteer (and other server-side headless browsers) do not have inherent restrictions against navigating to internal/private network addresses. Any user-controlled input determining navigation destinations must be heavily restricted to prevent network reconnaissance and internal system access.
**Prevention:** Implement a strict allowlist or blocklist for URLs prior to headless browser execution. Specifically, restrict protocols to `http:` and `https:`, and explicitly block loopback, private IP space, and cloud metadata IP ranges using `URL` parsing to handle varied URL formats reliably. Avoid returning raw stack traces by catching errors and throwing sanitized `BadRequestException`s.
